# Reproducing the analysis and paper figures

This guide separates three different tasks:

1. verifying the public analytic identities;
2. regenerating the submitted figure assets from the exact curated arrays;
3. rerunning the finite-element boundary-value problems that produced those
   arrays.

Tasks 1 and 2 do not require FEniCSx. Task 3 is a substantially more expensive
independent recomputation and is not needed merely to redraw the figures.

## 1. Fast path from a clean clone

The analytic and figure workflow was tested with Python 3.13.

```bash
git clone https://github.com/tengzhang48/nonlinear-symplectic-mooney-rivlin-crack-tip.git
cd nonlinear-symplectic-mooney-rivlin-crack-tip
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
```

Run the analytic and claims checks:

```bash
python tests/run_verification.py
python tests/check_claims.py
python analysis/profile_mode_audit.py --check-stored
```

The verification runner should finish with

```text
All 13 public verification programs passed.
```

It includes the 58-check equation suite and the consolidated analysis suites.
The counts describe heterogeneous, partly overlapping gates; they are not 13
independent proofs.

Render the stored-data figure set:

```bash
python figures/make_figures.py
```

Then verify the committed bytes:

```bash
sha256sum -c MANIFEST.sha256
```

The render command writes PDF and PNG assets under `figures/rendered/` and
refreshes `data/derived/profile_mode_audit.json` through the corrected profile
audit. It fails before plotting if a required input is absent.

## 3. Regenerating derived analytic artifacts

The selected leading angular profile is deterministic:

```bash
python data/analytic/build_profile.py
```

The corrected profile-mode audit can be recomputed from the curated disk and
strip inputs:

```bash
python analysis/profile_mode_audit.py --write
```

This updates

```text
data/derived/profile_mode_audit.json
figures/rendered/fig_profile_correction.pdf
figures/rendered/fig_profile_correction.png
```

Ordinary users should not run `make_manifest.py` after an exploratory change,
because that would bless changed bytes locally. Maintainers update the
manifest only after reviewing and accepting a regeneration.

## 4. Stored-data reproduction versus fresh simulation

The tracked arrays are the exact inputs used by the public renderings:

- `data/fem/strip/` contains the primary pure-shear evidence;
- `data/fem/disk/` contains the secondary deeper-window cross-check; and
- `data/analytic/` contains the selected leading angular profile.

The stored-data route answers:

> Do the archived inputs regenerate the reported summaries and figures under
> the current public analysis code?

A fresh finite-element solve answers a different question:

> Does the pinned solver and mesh construction independently reproduce the
> archived boundary-value result within the declared numerical tolerances?

Neither route should silently substitute for the other.

## 5. Fresh FEniCSx recomputation

Create the tested solver environment:

```bash
conda env create -f environment-fem.yml
conda activate mr-crack-tip-fem
```

Example disk solve:

```bash
(cd fem && python run_one_case.py \
  --c1 1 --c2 1 --lam 2.0 --tag MR_lam20)
```

Example primary pure-shear solve:

```bash
(cd fem/pure_shear && python run_ps.py \
  --c1 1 --c2 1 --lam 1.6 --tag MR_lam16)
```

Fresh output is written under ignored `outputs/` directories. The figure code
does not consume it implicitly. To replace a curated input, first verify the
mesh, continuation, case metadata, numerical tolerances, and cross-file
provenance described in [`data/README.md`](data/README.md) and
[`fem/README.md`](fem/README.md).

The production strip mesh uses 120 angular sectors and aligns the two nearest
interior rays exactly with the far corners. The `c2/c1=1/3` production case
uses 32 initial continuation subdivisions. These settings are stored in the
curated artifacts and checked by `tests/check_claims.py`.

## 6. Rebuilding the ESI mesh figure

With the FEniCSx environment active, run from the repository root:

```bash
python figures/make_esi_mesh.py
```

This constructs the strip and disk meshes afresh. It does not read a stored
mesh image.

## 7. What is and is not reproduced

The public package reproduces:

- leading constrained-field identities;
- the exact opening-block pairing checks;
- the bounded higher-order blocks listed in `CODE_MAP.md`;
- stored-data FEM comparisons and derived fits;
- every current main-paper figure;
- both current ESI figures; and
- the hashes and provenance of the public inputs and outputs.

It does not claim to reproduce:

- a completed all-grade coupled Hamiltonian operator;
- global matching that selects `Cs`, `B`, or `Q_k`;
- a universal raw `2/5` face profile;
- unfinished higher-order reaction amplitudes; or
- publisher-owned reference PDFs or internal review records.

The concise theory chain and these claim boundaries are recorded in
[`THEORY_NOTES.md`](THEORY_NOTES.md).

## 8. Maintainer release check

After an accepted code, note, data, or figure change:

```bash
python tests/run_verification.py
python tests/check_claims.py
python analysis/profile_mode_audit.py --check-stored
python figures/make_figures.py
python make_manifest.py
sha256sum -c MANIFEST.sha256
git diff --check
```

Run the manifest generator last. Review the manifest diff and rendered figures
before committing. The public release procedure is documented in
[`PUBLICATION_WORKFLOW.md`](PUBLICATION_WORKFLOW.md).
